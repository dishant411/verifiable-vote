# Contributing

Reproduce the local demo and run `bash scripts/demo.sh test`. Describe the upstream capability or demonstrated gap a change addresses. Prefer upstream fixes and small wrappers over copied UI, duplicate authentication stacks or new cryptography. Keep synthetic data only. Explain actual verification results and limits; do not weaken tests to hide failures. Protocol changes need review of anonymity, coercion, trustee and eligibility assumptions. See SECURITY.md for sensitive reports.
